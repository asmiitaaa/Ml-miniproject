# Evaluation dashboard

From the project folder, after installing `requirements.txt`:

```powershell
python -m streamlit run dashboard.py -- --results results
```

Use the URL printed by Streamlit, normally `http://localhost:8501`. To inspect a smoke test instead, pass its output directory. Stop the server with `Ctrl+C` in the terminal that started it. The sidebar also accepts a different output folder or a `runs.csv` path without restarting the server. An uploaded CSV works for summary tables; raw queue traces remain available only when their original run directories are present locally.

The application reads real evaluation records; it never inserts fabricated demonstration values. Missing DQN runs, fewer than five seeds, a single demand scenario, incomplete trips, missing metrics and inconsistent demand hashes appear as warnings. Smoke and demonstration experiments retain their labels.

## Views

- **Controller comparison:** choose one of the five required measures. Bars show means across selected seeds; error bars show sample standard deviation. The complete summary table includes the number of valid seeds for every metric.
- **Paired improvements:** compare each controller with fixed-time or actuated control. Pairs must share the same scenario, seed and nonempty `demand_hash`. Percentage reduction is computed for each seed before calculating its mean and sample standard deviation. Zero baselines are excluded because their percentage change is undefined. A negative percentage is a regression. The actuated waiting-time sanity check reports what the runs measured; a failed check must be investigated rather than removed from the results.
- **Intersection queues:** select a recorded run, intersection and approaches. The time series comes from `raw/.../queues.csv`; the chart may thin long traces for display, while the CSV download preserves all selected rows.
- **Training:** optionally point to a genuine Stable-Baselines3 Monitor CSV (`r,l,t`, with an optional initial `#` metadata line). The dashboard plots episode reward and a ten-episode moving mean. Evaluation results are never used to manufacture a training curve.
- **Run records:** inspect and download selected runs, including completion counts and provenance fields.

Filters for scenario, controller and seed update all result views and downloads. Use all five to ten prescribed seeds and both peak and off-peak scenarios for the final comparison. Selecting fewer seeds is useful for debugging but does not satisfy that requirement.

```powershell
python -m streamlit run dashboard.py -- --results results --training-log training/peak.monitor.csv
```

## Data contract

`runs.csv` must contain one row per `scenario,controller,seed`, with these numeric metrics:

| Column | Meaning |
|---|---|
| `avg_waiting_time_s` | Mean SUMO `waitingTime` among completed trips, seconds |
| `avg_trip_duration_s` | Mean SUMO `duration` among completed trips, seconds |
| `avg_queue_length` | Time-average halting vehicles per observed approach |
| `max_queue_length` | Maximum observed halting count on one approach |
| `co2_kg` | Integrated simulated CO₂ emissions, kilograms |

Recommended columns are `completed_trips`, `unfinished_trips`, `completion_rate`, `experiment_label`, `demand_hash`, and `run_dir`. Relative `run_dir` paths are resolved against the result folder, its parent, and the current directory, in that order. Queue CSVs use `time,tls_id,approach_id,queue_length`. Duplicate run identities are rejected so repeated experiments are never silently pooled.

Independent final comparisons must also retain manifests, controller/checkpoint identities, software versions and original demand files generated by the evaluation harness. Matching demand hashes establishes matched inputs, not a guarantee of identical vehicle trajectories: changing the controller naturally changes trajectories.

Standard deviations use `ddof=1`; one seed yields an undefined SD rather than zero uncertainty. Completed-trip averages can look optimistic if severe congestion prevents other vehicles from finishing. Always examine completion counts, unfinished trips and CO₂ coverage alongside delay metrics.

The dashboard is read-only except for browser-initiated CSV downloads. It does not train models or alter signal timings. Demonstration recordings and the report belong with the experiment artifacts; they must use the same scenarios and seeds as the evaluated runs.
